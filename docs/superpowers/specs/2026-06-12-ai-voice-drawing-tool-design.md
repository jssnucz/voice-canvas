# AI 语音绘图工具 —— 项目设计书

---

## 一、项目定位

### 1.1 产品定义

**AI 语音绘图工具** —— 一款纯语音驱动的软件工程图表绘制应用。用户无需鼠标键盘，仅通过自然语言描述，即可完成流程图与架构图的创建、编辑、迭代。

### 1.2 核心价值主张

面向**软件工程师、架构师、技术产品经理**在方案讨论、设计评审、技术文档编写等场景中，需要"快速把想法变成图"的需求。解决三个痛点：

| 痛点 | 传统方式 | 本产品 |
|------|---------|--------|
| 画图打断思考 | 手动拖拽、对齐、连线，操作繁琐 | 边说边画，思维不被工具打断 |
| 修改成本高 | 调位置、改样式需要多次点选 | "把登录模块变红"一句话完成 |
| 思维-图表脱节 | 讨论时停下来操作工具，思路被打断；画完图需要额外写文档解释 | 语音描述即图表生成，讨论结束图表同步产出，思维流不中断 |

### 1.3 差异化定位

本产品聚焦软件工程图表绘制领域，不做通用画板。相比同类工具的差异：

- **领域聚焦**：专攻软件工程图表，指令体系具有领域语义
- **AI 适度协作**：架构图场景下 AI 主动建议补全典型组件，流程图场景保持工具纯粹性
- **多模态指代消解**：关键帧策略——模糊指代时发画布截图给多模态模型精准定位
- **全链路延迟控制**：端侧拦截 25+ 高频指令 + 模型分层调用 + 流式渲染反馈

## 二、功能规划

### 2.1 图表类型支持

| 图表类型 | 计划 | 核心元素 | 说明 |
|---------|------|---------|------|
| **流程图** | ✅ P0 | 开始/结束(圆角矩形)、处理(矩形)、判断(菱形)、连线(实线箭头) | 深度支持，含分支、循环 |
| **架构图** | ✅ P0 | 服务(矩形)、数据库(圆柱体)、消息队列、缓存、API网关、同步调用(实线箭头)、异步消息(虚线箭头) | 深度支持，区分调用语义是专业感关键 |
| **时序图** | ⚠️ P1 | 参与者(矩形)、生命线(虚线)、消息箭头(实线)、返回箭头(虚线) | 线性结构天然适合语音描述 |
| **用例图** | ⚠️ P2 | 参与者(小人 👤)、用例(椭圆)、系统边界(方框) | 基础支持 |
| **ER图/类图** | ⚠️ P2 | 实体(矩形)、属性列表、关系连线 | 数据模型可扩展，基础支持 |

### 2.2 语音指令体系

#### 第一层：基础绘图指令（端侧执行，<100ms）

**创建类：**
```
"画一个矩形" / "加一个判断节点" / "这里需要一个开始节点"
→ 映射到具体图形类型，在当前视口中心或指定位置创建
```

**选择/聚焦类：**
```
"选中订单服务" / "聚焦到支付模块" / "看下一个"
→ 被选中元素高亮，后续修改指令默认作用于该元素
→ 降低多模态指代消解触发频率，让指代链条更可靠
```

**修改类：**
```
"把它变大一点" / "让这个颜色更深" / "文字改成'用户登录'"
→ 操作当前选中的元素，或最近提及的元素
```

**移动类：**
```
"往左移一点" / "把这个放到它的右边" / "对齐这两个节点"
→ 位置微调、相对定位、对齐操作
```

**连线类：**
```
"把 A 连到 B" / "从这里画一条线到那个判断节点"
→ 创建带箭头的连线
```

**删除/撤销类：**
```
"删掉它" / "撤销" / "重做" / "清空画布"
```

#### 第二层：复杂指令（云端 LLM，<2s）

**批量操作：**
```
"画一个用户登录流程，包含开始、判断是否登录、登录页、首页四个节点"
→ 一次生成多节点流程图
```

**样式批量修改：**
```
"把所有判断节点标成黄色"
→ 遍历匹配 + 批量更新
```

**布局调整：**
```
"让这些节点垂直排列" / "把这一排对齐"
→ 计算目标坐标 + 批量移动
```

**查询类：**
```
"当前画布上有哪些服务？" / "这个节点连到了哪些？" / "有没有孤立节点？"
→ AI 语音回复，不操作画布
→ 评审场景实用，展示 AI 对画布的"理解力"
```

#### 第三层：AI 协作指令（架构图 + 时序图场景）

**模板建议：**
```
"画一个微服务架构"
→ AI 生成服务、网关、数据库、缓存等组件，主动确认：
  "检测到微服务架构，我添加了 API 网关和消息队列。订单系统通常还需要支付网关和库存服务，需要我补上吗？"
```

**补全追问：**
```
用户："画一个订单系统架构"
AI 补充："订单系统通常需要支付网关和库存服务，要我加上吗？"
```

**时序图推导：**
```
"A 调用 B 的登录接口，B 返回 token，A 用 token 调用 C"
→ AI 生成参与者 + 生命线 + 消息序列
```

### 2.3 多模态指代消解

```
触发条件：用户指令包含模糊指代词（"那个""它""这个"）
         且文本上下文 + 选中状态无法消歧

处理流程：
  1. 截取当前画布视图 → 生成 PNG
  2. 连同用户指令 + 元素 ID 列表发给 DeepSeek-V4.5
  3. 模型视觉定位 → 返回 target_id + 置信度
  4. 高置信度 → 直接执行操作
     低置信度 → 前端高亮候选元素，语音提示用户确认

降级策略（双保险）：
  - 模型视觉不可用时 → 回退到文本上下文匹配 + 最近提及元素
  - 模型视觉低置信度时 → "您是说[元素A]还是[元素B]？"
```

### 2.4 辅助功能

| 功能 | 描述 | 触发方式 |
|------|------|---------|
| 撤销/重做 | 命令模式操作历史栈，支持连续 20 步撤销 | "撤销""重做" |
| 主题切换 | 预设 3 套专业配色（浅色/深色/蓝灰） | "换成深色主题" |
| 缩放/平移 | 画布视图控制 | "放大""缩小""往右移"（画布级） |
| 导出图片 | PNG/SVG 导出，分辨率 ≥ 当前视口 2x | "导出成图片" |
| 语音标记 | 在指定位置创建便签/注释节点 | "在这里加个备注：需要和支付团队确认接口" |
| 语音反馈 | 三段式动画（听→想→执行），消除黑盒感 | 全流程自动触发 |

| 类别 | 指令示例 | 数量 |
|------|---------|------|
| 创建基础图形 | 画矩形/菱形/圆/圆柱/箭头/小人 | 6 |
| 删除 | 删除/移除/去掉 | 3 |
| 撤销/重做 | 撤销/重做/回退 | 3 |

| 样式预设 | 变红/蓝色/绿色/黄色/变大/变小 | 6 |

#### 决策规则与冲突处理

```
优先级链（高→低）：
  1. 模糊指代词（"那个""它"） → 多模态管道（V4.5）
  2. 图表生成关键词（"流程""架构"） → 批量生成管道（V4.5）
  3. 查询关键词（"有哪些""连到哪""有没有"） → 查询管道（V4-Lite）
  4. 端侧命中规则 → 本地执行

本地执行前置检查：
  - 必须存在 selectedId 或 lastMentionedId
  - 指令中不含模糊指代词
  - 不满足 → 升级至对应云端管道

多条件冲突案例：
  "把那个判断节点变红"     → Rule 1 命中 → 多模态管道
  "把判断节点变红"         → Rule 4 命中 → 本地执行（有选中目标时）
  "画一个微服务架构"       → Rule 2 命中 → 批量生成管道
  "这个节点连到了哪些"     → Rule 1 + 3 同时 → Rule 1 优先 → 多模态管道
```

### 3.3 核心数据模型

```typescript
// ========== 画布元素 —— 贯穿全栈的唯一真相 ==========
interface CanvasElement {
  id: string;                          // 唯一标识，如 "elem_001"
  type: ElementType;                   // 图形类型
  label: string;                       // 显示文本
  voiceAliases: {
    auto: string[];                    // LLM 创建时自动生成，如 ['登录模块', '那个登录的', '登录框']
    manual: string[];                  // 用户手动添加（可选）
  };
  position: { x: number; y: number };  // 画布坐标
  size: { width: number; height: number };
  style: {
    fill: string;                      // 填充色
    stroke: string;                    // 边框色
    fontSize: number;
    fontWeight: 'normal' | 'bold';
  };
  metadata?: Record<string, unknown>;  // 扩展字段（注释内容等）
}

type ElementType =
  | 'rounded-rect'    // 开始/结束
  | 'rect'            // 处理/服务
  | 'diamond'         // 判断
  | 'cylinder'        // 数据库
  | 'ellipse'         // 用例
  | 'actor'           // 参与者
  | 'queue'           // 消息队列
  | 'cache'           // 缓存
  | 'gateway'         // API 网关
  | 'lifeline'        // 生命线（时序图）
  | 'sticky-note';    // 便签/备注

// ========== 连线 —— React Flow 原生支持 ==========
interface CanvasEdge {
  id: string;
  source: string;       // 起始节点 ID
  target: string;       // 目标节点 ID
  type: 'solid' | 'dashed';  // 实线=同步调用，虚线=异步消息
  label?: string;
  style: EdgeStyle;
}

// ========== LLM 必须返回的操作指令 ==========
interface DeltaCommand {
  action: 'create' | 'update' | 'delete' | 'move' | 'connect';
  targets: string[];              // 目标元素 ID 列表
  payload?: {
    elements?: Partial<CanvasElement>[];
    edges?: Partial<CanvasEdge>[];
    layout?: 'vertical' | 'horizontal' | 'grid';
  };
  reasoning?: string;             // AI 解释推理过程（调试/透明度用）
}

// ========== 操作历史（命令模式） ==========
interface CommandRecord {
  id: string;
  timestamp: number;
  command: DeltaCommand;
  inverse: DeltaCommand;          // 逆操作，支撑撤销
  utterance: string;              // 触发的原始语音文本
}

// ========== 图表上下文 ==========
interface DiagramContext {
  mode: 'flowchart' | 'architecture' | 'sequence' | 'usecase';
  elements: Map<string, CanvasElement>;
  edges: CanvasEdge[];
  selectedId: string | null;       // 当前选中元素
  lastMentionedId: string | null;  // 最近提及的元素
  history: CommandRecord[];        // 操作历史栈
  historyIndex: number;            // 当前位置（支持重做）
}
```

**设计要点：**

- `voiceAliases.auto`：LLM 在创建元素时自动生成 2-3 个口语化别名，如标签为"用户登录模块"的节点自动生成 `['登录模块', '那个登录的', '登录框']`。用户零负担，LLM 生成的语言更贴近自然口语，匹配率更高。元素标签被修改后，别名也自动刷新。
- 前后端 TypeScript 统一，此数据模型作为单一数据源贯穿全栈，编译期即可捕获类型不一致。

### 3.4 Prompt 设计策略

#### 系统级 Prompt 结构

```
你是一个软件工程图表绘制助手。你的任务是：
1. 理解用户的自然语言绘图指令
2. 输出精确的 DeltaCommand JSON 数组

核心规则：
- 每次只输出操作指令，不要输出解释文字
- 流程图必须符合 DAG（有向无环图）结构
- 架构图组件布局避免重叠，留有间距
- 指代消解：优先用 voiceAliases 匹配，其次看上下文
- 时序图参与者从左到右排列，生命线向下延伸
- 每次创建元素时，自动生成 2-3 个用户可能用来指代该元素的语音别名
- 如果用户一句话包含多个操作，请拆解为 commands 数组
- 不确定时，设置 action: "query" 反问用户

输出格式（严格 JSON）：
{ "commands": DeltaCommand[] }
```

#### 图表类型专用 Prompt 补充

| 图表类型 | 补充规则 |
|---------|---------|
| 流程图 | 开始节点只有出边，结束节点只有入边，判断节点必须有两条分支出口 |
| 架构图 | 区分同步调用(实线)和异步消息(虚线)，数据库用圆柱体。用户描述微服务/分布式/电商等架构时，主动建议典型缺失组件 |
| 时序图 | 时间轴自上而下，激活框表示处理期间，返回用虚线箭头 |
| 用例图 | 参与者(小人)在系统边界外，用例(椭圆)在边界内 |

#### 三段式语音交互动画

| 阶段 | 管道 | 视觉反馈 | 时长 |
|------|------|---------|------|
| 🎤 听 | 全部 | 画布边缘蓝色脉冲呼吸灯，实时显示识别文本 | ASR 期间 |
| 🤔 想 | 端侧执行 | **无等待**，直接进入"执行"阶段 | — |
| 🤔 想 | V4-Lite 文本管道 | 顶部细进度条 + "正在理解..." | API 调用期间 |
| 🤔 想 | V4.5 多模态管道 | 画布轻微灰显 + 缩略图动画 + "正在分析画面..." | 截图上传 + 视觉推理期间 |
| ✅ 执行 | 全部 | 轮廓填充 + 微弹出动画，元素到位 | 操作完成瞬间 |

差异化等待反馈的设计意图：用户能感知"这次操作比较复杂，AI 正在仔细看画面"，而非"卡住了"。

### 3.6 自动布局策略

| 图表类型 | 布局算法 | 实现方式 |
|---------|---------|---------|
| 流程图 | DAG 层级布局（Sugiyama 算法变体） | Dagre 库计算节点坐标，喂给 React Flow |
| 架构图 | 决策边界：节点 ≤5 且用户描述明确空间关系 → LLM 直接输出坐标；节点 >5 或未描述空间关系 → D3-force 力导向布局 | 前端判断条件后选择策略 |
| 时序图 | 固定模板：参与者等距排列，生命线向下 | 前端计算，不依赖算法库 |
| 用例图 | 网格分区：系统边界内网格放置用例 | 前端计算 |

架构图布局决策边界的设计意图：避免 LLM 在复杂场景下输出不合理坐标（如 10 个节点堆叠），同时发挥 LLM 在简单场景下的灵活性。

### 3.7 异常处理与降级策略

| 异常场景 | 处理策略 |
|---------|---------|
| LLM 返回非法 JSON | Zod 校验失败 → 自动重试一次（附带错误信息）→ 仍失败则语音提示"请换个方式描述" |
| LLM 返回的 element_id 不存在 | 降级为创建新元素，而非更新不存在的元素 |
| ASR 识别置信度过低 | 显示识别文本 + 问号标记，语音提示"您是说...吗？" |
| 网络超时（>5s） | 语音提示"网络不太稳定，请稍后重试" + 保留当前指令在待处理队列 |
| 多模态截图失败 | 降级为纯文本消解（voiceAliases + lastMentionedId），语音告知用户 |
| 画布截图 canvas 为空 | 返回文本管道处理，不发送空截图 |

## 四、核心重难点与解决方案

### 4.1 重难点矩阵

| 重难点 | 风险 | 根源分析 | 解决方案 | 关键依赖 |
|--------|------|---------|---------|---------|
| **多模态指代消解** | 🔴 高 | 口语化指代高度依赖视觉上下文，纯文本无法消歧 | 关键帧截图 + V4.5 视觉定位 + 置信度门控 + 低置信度时语音确认 | V4.5 视觉稳定性 |
| **LLM 结构化输出稳定性** | 🔴 高 | LLM 本质是概率模型，JSON 格式可能不合规 | 强制 JSON 模式 + Zod 双层校验 + 失败自动重试 + 降级兜底 | System Prompt 质量 + Zod Schema 严谨度 |
| **画布-LLM 状态同步** | 🟡 中 | 多轮对话中，LLM 上下文可能滞后于画布实际状态 | 每次请求携带画布元素摘要（ID+类型+标签+坐标）注入 Prompt；操作后即时更新摘要缓存 | 摘要生成效率 + Prompt 长度控制 |
| **全链路延迟** | 🟡 中 | 语音→ASR→意图分类→LLM→渲染，任一环节积压则体验崩 | 端侧拦截 25+ 高频指令 + 模型分层调用 + 流式 ASR 中间结果预判 | 端侧分类器覆盖率 + V4-Lite 响应速度 |
| **自动布局美观度** | 🟡 中 | 算法布局可能不符合人类审美直觉 | Dagre (流程图) + D3-force (复杂架构) + LLM 直接坐标 (简单场景) + 预设模板 | Dagre / D3-force 库 |
| **时序图渲染** | 🟡 中 | React Flow 无原生生命线 + 激活框概念 | 自定义 React Flow 节点类型：ParticipantNode + LifelineEdge + ActivationBar | React Flow 自定义节点/边 API |
| **语音识别准确性** | 🟢 低 | Web Speech API 对中文 IT 术语可能偏差 | 领域词库注入 + 置信度门控 + 上下文纠错 | 浏览器原生 API |
| **连续指令拆解** | 🟢 低 | 一句话含多个操作需正确分解，但深度推理非必需 | Prompt 规则："若含多个操作，拆解为 commands[]"，LLM 基础能力即可胜任 | LLM 基本推理能力 |

| 重难点 | 对应 US | 为什么 |
|--------|---------|--------|
| 多模态指代消解 | **US-05** | "把那个红色的菱形变大" |
| LLM 结构化输出 | **US-01, US-04** | 流程图/架构图生成的可靠性 |
| 画布-LLM 状态同步 | **US-02** | 多轮修改的一致性 |
| 全链路延迟控制 | **US-02, US-03** | 修改、撤销的响应体验 |
| 自动布局美观度 | **US-01, US-04** | 生成图表的专业感 |
| 时序图渲染 | **US-06** | 图表模式切换 → 时序图能力 |
| 语音识别准确性 | **全部 US** | 所有指令的基础入口 |
| 连续指令拆解 | **US-08** | 快速连续指令的分解执行 |

## 五、运营成本控制策略

| 编号 | 策略 | 描述 | 预估节省 | 计划 |
|------|------|------|---------|------|
| C-01 | 端侧意图拦截 | 浏览器端识别 25 个高频指令，直接执行不调云端 | 30-40% API 调用 | ✅ |
| C-02 | 模型分层调用 | 简单指令走 V4-Lite（成本约 V4.5 的 1/5），复杂/视觉指令走 V4.5 | 40-50% 单次成本 | ✅ |
| C-03 | 关键帧发送 | 不是每句话都发截图，仅模糊指代时发送（预计占所有指令的 15-20%） | 80% 图片 Token | ✅ |
| C-04 | 对话历史截断 | 超过 128K 上下文时，保留摘要 + 最近 5 轮 + 当前画布元素摘要 | 避免长对话成本膨胀 | ✅ |
| C-05 | 画布摘要代替全量历史 | 每次请求注入结构化元素摘要（~500 tokens），而非全量对话历史 | 减少上下文 Token | ✅ |
| C-06 | 预设模板骨架 | 流程图/架构图/时序图的节点样式和默认布局前端预置，LLM 只输出节点内容+位置 | 减少输出 Token 30% | ⚠️ |

### 第一幕：流程图（~1:00）— 展示基础语音绘图能力

| 时间 | 语音指令 | 预期效果 | 亮点 |
|------|---------|---------|------|

### 容错备手（~0:30，可选）

> "为了展示系统的鲁棒性，我故意说一个模糊指令——**'把那个东西删掉'**。注意看，系统没有直接操作，而是高亮了最近提及的元素并语音确认：**'您是指判断节点吗？'** 这是我们的置信度门控机制——当 AI 不确定时，它会主动确认而非盲猜。"

（脚本备注：此段不强行插入主动演示流，作为评委提问"识别错了怎么办"或现场出现小状况时的自然切入口，变被动为主动。）

### 脚本设计原则

- 每幕有明确的"记忆点"（流程图效率 → 多模态惊艳 → AI 协作智慧）
- 真实需求讨论场景驱动，不是功能罗列
- 每个 P0 用户故事在脚本中有对应触发时机
- 指令之间留有缓冲，不追求无缝衔接
- 容错备手预留，变 Bug 为 Feature

### 8.1 与现有工具的差异化分析

| 维度 | Draw.io / ProcessOn | 通用语音助手 | **本产品** | 为什么用户在意 |
|------|--------------------|------------|-----------|--------------|
| 交互方式 | 鼠标拖拽为主 | 文本对话 | **语音对话为主** | 讨论方案时不被工具操作打断 |
| 学习成本 | 需学习工具操作 | 无 | 零学习，自然语言 | 架构师不需要学新工具 |
| 图表领域 | 通用 | 通用 | **软件工程图表专精** | 领域语义理解更深，生成更专业 |
| 指代修改 | 手动点选 | 文本模糊匹配 | **多模态视觉定位 + 文本消解双通道** | 不用记元素编号，说"那个红的"就行 |
| AI 主动性 | 无 | 被动响应 | **架构图场景主动建议补全** | 减少评审盲区，不遗漏典型组件 |
| 图表专业性 | 需手动调整 | 无布局优化 | **Dagre/D3-force 自动布局 + 实线/虚线语义区分** | 架构评审时连线语义是关键信息 |
| 操作延迟 | — | 全走云端 | **端侧 25+ 指令 <100ms + 模型分层** | 修改和撤销不用等，思维不被打断 |
| 查询能力 | 手动查看 | 可能不支持 | **语音查询画布内容** | 评审中不用手动数节点，AI 替你看 |
