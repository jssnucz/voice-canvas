## 二、意图分类器全量规则清单

当前 `intentClassifier.ts` 实际实现的全部规则（按优先级排序）：

```
优先级 1: AMBIGUOUS_REFS          → 多模态管道 (V4-Pro)
  "那个"、"这个"、"这个东西"、"这东西"、"那个东西"

优先级 2: GENERATE_KEYWORDS       → 批量生成管道 (V4-Pro)
  "流程"、"架构"、"时序"、"用例"、"类图"、"微服务"

优先级 3: QUERY_KEYWORDS          → 查询管道 (V4-Flash)
  "有哪些"、"连到了哪"、"有没有"、"几个"、"多少"

优先级 4: 本地指令（端侧执行）
  ├── undo         /撤销|回退|撤回/
  ├── redo         /重做|恢复|前进/
  ├── zoom-in      /放大/                    (无 target 时)
  ├── zoom-out     /缩小/                    (无 target 时)
```

## 三、未完成功能及原因

### 3.1 时序图深度实现（P1 → 部分完成）

| 项目 | 状态 | 原因 |
|------|------|------|
| 模式切换 | ✅ 已实现 | 语音 "切换到时序图模式" 可用 |
| 参与者渲染 | ❌ 未实现 | React Flow 自定义 `ParticipantNode` 未开发 |
| 生命线 | ❌ 未实现 | 需要自定义边类型 `LifelineEdge`，仅 `lifeline` 元素类型已预留 |
| 激活框 | ❌ 未实现 | 需要自定义节点 + 动态高度计算 |
| 消息序列 | ❌ 未实现 | 依赖生命线和激活框就位 |

**原因**：时序图在 React Flow 中没有原生支持，需要开发 3 个自定义节点类型 + 2 个自定义边类型 + 时间轴布局算法。四周周期内优先保证流程图和架构图的完整体验链路。数据模型已预留 `lifeline` 元素类型，后续可在此基础上扩展。

### 3.2 自动布局引擎（P2 → 未开始）

**原因**：设计已完成（决策边界 ≤5 节点用 LLM 坐标，>5 节点用 Dagre/D3-force）。当前 LLM 直接输出坐标在 ≤5 节点场景下效果可接受，复杂场景的多节点堆叠问题尚未触发。Dagre 和 D3-force 已列入技术栈但未集成到命令执行链路。

### 3.3 深色/蓝灰主题（P2 → 未开始）

**原因**：Zustand store 已预留 `theme` 字段（`'light' | 'dark' | 'blue-gray'`），ELEMENT_DEFAULTS 仅实现了白色主题配色。主题切换需要为每个元素类型准备 3 套配色方案 + Tailwind 暗色模式集成，属于锦上添花功能。

### 3.4 用例图完整支持（P2 → 未开始）

**原因**：基础元素（小人 `actor`、椭圆 `ellipse`）已预留数据模型 + React Flow 自定义节点。完整交互需要：系统边界渲染、用例间关系（include/extend/generalization）、参与者-用例通信连线。这些建模概念在技术评审场景中使用频率低于流程图和架构图。

### 3.5 ER 图/类图（P2 → 未开始）

**原因**：数据模型可扩展（`CanvasElement` 的 `metadata` 字段可承载属性列表）。但类图的继承/实现/聚合/组合关系连线需要新增边类型，ER 图的实体-属性结构需要嵌套渲染。当前聚焦流程图 + 架构图两大核心类型。
